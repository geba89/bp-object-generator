Blue Prism Object Generator

Builds a page object from scanned XPaths, using your own template object. Runs fully offline: nothing leaves this computer.

1. Template object

No template yet? Build one from your Chrome object
Export your Chrome object from Blue Prism (File → Export) and load it here. The file stays on this computer. The generator reads the inputs of your dynamic action and builds a complete template object whose pages all call it.
Fix or repair an object you already generated (references, Clean Up page, object info)
Every Action stage calls another object by name. If the name is wrong, all steps break at once. Load the exported object here, type the right names (or fix ONE stage by hand in Blue Prism, export, and use Use for all on that row), and download the fixed file. Nothing leaves this computer.
How to build the template object
  1. Create a new object, e.g. TPL - Page Object Template.
  2. Add one page per step type, named exactly: TPL Click, TPL Set Text, TPL Get Text, TPL Select From List, TPL Select Radio, TPL Set Checkbox, TPL Read Table. Optional: TPL Click (Row) / TPL Get Text (Row) for buttons inside table rows, TPL Set Password for password fields.
  3. On each page: Start (with inputs if needed) → Action stage calling your Chrome object → End (with outputs if needed).
  4. In the Action stage, set the XPath input to the expression "{{XPATH}}" (quotes included).
  5. Inputs every page needs (e.g. I_Title): give every TPL page the same input name; they are suggested as shared (once per action).
  6. TPL Select Radio: a start input Option (Text) lets one action select any option of a radio group.
  7. Row variants: a start input Row Key (Text).
  8. Skip empty inputs: not needed in the template any more – the generator adds a Decision per step (Order screen: Runs: skip if empty).
  9. Read-back checks (optional): TPL Verify Text, TPL Verify Select (and TPL Verify Checkbox / TPL Verify Radio). Start with your shared inputs plus ONE expected-value input (e.g. I_Expected); read "{{XPATH}}"; compare with the expected value; on a difference throw an Exception, e.g. "field shows " & [Actual] & ", expected " & [I_Expected]
    Dropdowns: reading a <select> returns all its options, so TPL Verify Select must read the selected item; without that page dropdowns get no check. (with TPL Error Handler the action name and step are added in front automatically; without it, use {{ACTION}} / {{FIELD}} here). The generator wires the expected value to the step's own input (I_City).
  10. TPL Error Handler (optional): a Recover stage → an Exception stage, plus a text data item Current Step. Exception detail e.g. "{{ACTION}} / " & [Current Step] & ": " & ExceptionDetail(). Every action gets a copy; before each step the generator sets Current Step (e.g. "Select Country").
  11. Placeholders you can use anywhere (names, descriptions, exception details): {{XPATH}}, {{FIELD}} (field name), {{LABEL}} (element label), {{ACTION}} (action name), {{DESCRIPTION}} (generated description). Tip: wrap a page's steps in a Block named {{FIELD}} – chained actions then read like a table of contents.
  12. TPL XPaths (optional): one data item, not hidden from other pages. It is the model for the XP ... data items.
  13. TPL Check Element (optional): check one element ("{{XPATH}}") and append "{{LABEL}}; " to an output Missing when it's not found. Becomes the Check Page Elements action.
  14. Data items on step pages: tick Hide from other pages in the process.
  15. Export it: File → Export, and load the file above.
Calls to other objects the object and action every generated step calls. They must match the names in Blue Prism exactly (spaces and case too); change them here if they differ.

Getting started

Three parts: the scanner finds the elements of a web page and their XPaths, this generator turns them into a Blue Prism object, and Blue Prism imports it. Everything runs on this computer.

1Add the scanner to Chrome or Edge (once)

  1. Open Chrome or Edge and press F12 to open DevTools.
  2. Open the Sources tab. On its left side open Snippets (if you don't see it, click » first).
  3. Click + New snippet and name it BP XPath Scanner.
  4. Copy the scanner with the button below, paste it into the snippet (Ctrl+V) and save (Ctrl+S).

2Scan each screen

  1. Open the application and go to the screen you need, e.g. Search.
  2. In DevTools: Sources → Snippets, right-click BP XPath Scanner → Run (or select it and press Ctrl+Enter).
  3. It asks for the screen name: type e.g. Search. Numbered badges appear on the page, and the CSV is downloaded as bp-xpaths-Search.csv and copied to the clipboard.
  4. Repeat on every screen the object needs (e.g. Edit, Not Found).

3Build the object here

  1. Template: load your template object, or build one from your Chrome object.
  2. Scan: load the CSV files (several at once is fine), or paste the CSV.
  3. Steps 3–5: group the fields into actions, check the order, generate, and import the .bpobject in Blue Prism.
Tips
  • Form inside an iframe? In the Console tab pick the frame in the top dropdown, then run the snippet: it runs in the selected frame.
  • Console instead of Snippets: paste the scanner into the Console and press Enter. Chrome may ask you to type allow pasting the first time.
  • After a generator update, copy the scanner again and replace the snippet's contents: the version is shown next to the Copy button.
  • After a scan, in the Console: BPScan.highlight(5) shows element #5, BPScan.clear() removes the badges.
  • Skip the screen-name question: run window.BP_SCAN_CONFIG = { askScreenName: false } in the Console first.
